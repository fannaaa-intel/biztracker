# BizTracker — Business Permit and Regulatory Compliance System

## What this is
A Windows desktop app for a Philippine municipality (LGU) that tracks six regulatory
services for local businesses in one place:

1. Business Permit (New / Renewal) — BPLO
2. Sanitary Permit — Municipal Health Office
3. Real Property Tax (RPT) — Assessor / Treasurer
4. Health Certificates (Food Handler / Non-Food) — Municipal Health Office
5. Annual Inspection (Structural, Electrical, Mechanical, Fire) — Joint Inspection Team
6. Construction Permit (Locational/Zoning → Building → Occupancy) — OBO / MPDO

Legal basis: RA 7160 (Local Government Code) and RA 11032 (Ease of Doing Business).
This is a solo student capstone project. Keep code simple, readable, and well commented.

## Tech stack (do not change without asking)
- Language: VB.NET
- UI: Windows Forms on .NET 8 (`net8.0-windows`)
- Database: MySQL (MariaDB) via XAMPP, `localhost:3306`, user `root`, empty password, database `biztracker_db`
- DB driver: `MySql.Data` NuGet package
- Password hashing: `BCrypt.Net-Next` NuGet package
- Printing/reports: generate an HTML file from a template and open it in the default browser (user prints or saves as PDF)
- Build: `dotnet build` / run: `dotnet run --project src/BizTracker`

## Architecture rules
- MainForm has a left sidebar + a content panel. Clicking a sidebar item loads that module's UserControl into the panel.
- Forms/UserControls NEVER contain SQL. They call Repository or Service classes.
- ALL SQL uses parameterized queries (`@param`). Never build SQL with string concatenation of user input.
- Use `Using` blocks for every connection/command/reader.
- Every screen reads live data from the database. NO hard-coded sample values in the UI.
- Statuses that depend on dates (Valid / Expiring Soon / Expired, Overdue) are COMPUTED in `StatusService` from `Date.Today`, not stored.
- "Expiring Soon" threshold = 30 days (store in `settings` table, key `expiry_warning_days`).
- Reference numbers are generated by `ReferenceNoService`, format `PREFIX-YYYY-00001` (e.g. `BP-2026-00001`, `SP-`, `HC-`, `INS-`, `CP-`, `OR-`).
- Uploaded files are copied into `uploads/<business_id>/` and only the relative path is saved in the database (no BLOBs).
- Insert/update/delete actions on important tables write a row to `audit_log` via `AuditService`.
- Deleting a business is a soft delete (`is_active = 0`). Use foreign keys with `ON DELETE RESTRICT`.
- Wrap DB errors in a friendly MessageBox; never crash on a DB error.

## Roles and access
| Role | Can access |
|---|---|
| Admin | Everything + User Management + Settings + Audit Log |
| BPLO | Businesses, Business Permits, Dashboard, Reports |
| Health | Sanitary Permits, Health Certificates |
| Assessor | Real Property Tax |
| Building | Construction Permits |
| Inspector | Annual Inspections |
| Owner | Read-only view of THEIR OWN business (all six modules + dashboard + vault), can upload requirements and file applications |

Owner users have `users.business_id` set; every query for an Owner is filtered by that business_id.
Sidebar items are hidden for modules a role cannot access.

## Business rules (Philippine LGU)
- Business permit renewal deadline: January 20 each year. Late = 25% surcharge + 2% interest per month (not compounded), max 36 months.
- RPT: basic tax 1% + SEF 1% of assessed value per year, payable quarterly (due end of each quarter). Late = 2% per month, max 72%.
- Health certificates are valid 1 year from issue date.
- Sanitary permits expire December 31 of the year issued.
- Keep rates in the `settings` table so they can be changed without code edits.

## Sample data rule
Seed data must tell ONE consistent story that matches across every screen
(dashboard numbers must equal what the module screens show). Use dates relative to
`CURDATE()` in the seed SQL (e.g. `DATE_ADD(CURDATE(), INTERVAL 20 DAY)`) so "Expiring Soon"
and "Overdue" alerts always appear during demos.
